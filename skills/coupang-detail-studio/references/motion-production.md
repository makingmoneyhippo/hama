# Motion production routes for product detail pages

A moving file is useful when it shows something the buyer cannot learn as quickly from a still. Classify each shot as **filmed proof**, **AI use recreation**, **explainer**, or **decoration** before choosing a tool. An AI recreation may explain a visually evidenced action but does not prove product performance.

## Default output timing

- Ordinary action: **3 seconds × 20 fps = 60 encoded frames**.
- Genuinely longer action: **4 seconds × 20 fps = 80 encoded frames**.
- Each output frame has a 50 ms delay. Choose the longer duration in the motion brief when the full action or natural loop requires it; do not slow an empty scene just to use 4 seconds.
- The output must contain smooth, meaningful progression. Repeating 6–16 source stills to hit 60/80 frames does not satisfy the motion standard. Generate sufficiently small action steps and interpolate only where inspected in-between frames preserve anatomy, product geometry, and background. If interpolation ghosts or warps, repair the source motion or obtain better footage instead of shipping the artifact.

| Route | Good use | Requirement |
|---|---|---|
| Existing product GIF/video | Evidence of actual opening, closing, swivel, installation, cleaning, or use | Inspect start/middle/end and intermediate frames to understand the selected SKU. Do not republish supplier or 1688 frames; use them only to brief and verify a newly made animation. User-owned original footage may be edited if its rights are clear. |
| New product footage | A central action missing from sources | Write a capture brief: camera angle, hands, starting state, full action, ending state, scale, lighting, duration, and option identity. Do not invent the action while waiting. |
| Deterministic animation from verified sources | Callouts, measured diagrams, accurate before/after, visual explanation | Rebuild diagrams or frames from verified facts without reusing supplier pixels. Do not fake a load, test, spring return, or rotation that was never observed. |
| Codex GPT Image frames → GIF → animated WebP | New short use action or scene motion supported by product sources | Start from one source-faithful image. Try native GIF only when the available Codex tool actually returns a multi-frame file. Otherwise ask for an equal-cell sequential frame sheet, crop each cell, and encode a real GIF locally. Convert the GIF to animated WebP with an encoder, never by renaming. Inspect all frames for topology, hand position, flicker, and action completion. Do not use Higgsfield to fill the target. |

## Production loop

1. At intake, record the user's animated WebP target as a count, percentage, `N/T`, or all. Define `T` as primary visual image panels, excluding icons, thumbnails, duplicate animations, and still fallbacks. For a percentage, round `T × percentage / 100` up. Put the target and planned panel IDs in the motion brief before production.
2. Inventory all source media, including hidden GIF/video in the reference URL, and record what actually moves. Extract representative frames rather than interpreting a first-frame screenshot as a still image.
3. For each planned animated panel record buyer question, the one useful change it shows, source evidence, format, 3- or 4-second duration, 60- or 80-frame target, start/action/end frame, crop, caption, repeat point, still fallback, and target Coupang field. Distinct panels need distinct motion, not the same loop repeated to reach the count. Label each as functional demonstration, explanation, or decoration. Decorative movement does not replace a missing use demonstration.
4. Choose editing first only for user-owned original footage with clear rights; supplier/1688 footage is reference-only. For newly generated animation, use the available Codex GPT Image tool with the exact SKU source image as reference, then create all output frames anew. If requesting an equal-cell frame sheet, specify the exact grid, reading order, fixed camera, fixed prop count, visible contact, and first/action/last states. Cut cells at their exact grid boundaries. Keep the unmodified generated sheet and extracted frames. Do not claim which image model version ran when the tool does not expose it. A single still with zoom is *decoration* and cannot clear the use-motion gate.
5. Encode a true multi-frame GIF and animated WebP for accepted sequences; MP4 is optional unless the target requires video. Renaming a file extension is not conversion. Run `python3 scripts/verify_animated_webp.py path/to/clip.webp` (or add `--seconds 4`) to verify exactly 60 or 80 frames and 50 ms delay per frame. Also check the loop seam, dimensions, byte size, and still fallback. Inspect **every** frame, especially hand/object contact, and compare the apparent speed with natural use. For a functional demonstration, the mechanism must visibly operate and the item must clearly reach its final state. Reject sudden action jumps, duplicated holds presented as smoothness, interpolation ghosts, product part drift, or distracting background flicker even when the metadata passes. Rework a failed slot or disclose the shortfall; do not count it as delivered.
6. Verify every animated WebP inside the one-page HTML preview before delivery. Report requested and delivered counts as `N/T`, with panel IDs and any shortfall. When the user later prepares Coupang publication, verify placement in the actual seller editor and its previewed result. Keep Coupang placement `untested` until then.

## Tool choice and cost

Use the Codex GPT Image tool for new frames and local encoding for GIF/WebP. Do not call Higgsfield or another hosted video generator to meet the animation count unless the user explicitly changes this preference. Native GIF support is tool-specific: [OpenAI's Image API reference](https://developers.openai.com/api/reference/python/resources/images/methods/generate) currently limits one GIF generation to 2–16 frames, and this does not prove the signed-in Codex tool exposes GIF controls. The 60/80 finished-frame standard therefore requires a well-planned multi-stage source sequence, careful local interpolation where it passes visual review, or user-owned authentic motion. API usage is metered separately from signed-in Codex; [eligible Pro and Business subscriptions can claim API credits](https://developers.openai.com/api/docs/guides/chatgpt-api-credits) after account linking. Do not assume credits, a usable API key, or unlimited native GIF output. [FFmpeg](https://ffmpeg.org/documentation.html) can encode the animated WebP, but its interpolation filter can visibly warp large jumps. If Codex image generation cannot produce truthful motion for a required slot, improve the brief or use authentic source footage; disclose any unresolved shortfall rather than silently routing to a paid tool.

For Coupang, the [official listing guide](https://marketplace.coupang.com/register) mentions JPG/PNG gallery imagery and describes image, editor, and HTML methods for the detail section. This does not establish animated WebP support in a detail editor or a video field. Test the exact field. If real footage is missing, an accurate generated use recreation can still explain an action supported by source photos. Keep source and generation provenance in the internal manifest without an automatic on-screen AI label; check any separately required legal disclosure. If the recreation cannot show the action without changing the product, provide a capture brief and mark the use-motion gate failed.
